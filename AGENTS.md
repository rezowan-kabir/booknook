# BookNook — Next.js 16 + React 19 (App Router)

## Commands

| Action | Command |
|--------|---------|
| Dev server (Turbopack) | `npm run dev` |
| Production build | `npm run build` |
| Production server | `npm run start` |
| Lint | `npm run lint` (bare `eslint`, flat config in `eslint.config.mjs`) |

**Verification gate = `npm run lint` then `npm run build`.** There is no `typecheck` script — `next build` runs `tsc` (`strict`, `noEmit`) and fails on type errors. **No tests, no CI** exist; if you add tests, pick a framework and add the script yourself. Lint exits 0 with warnings (8 currently: unused vars, one `<img>`), so warnings are tolerated — errors are not. One error rule that bites: `react-hooks/set-state-in-effect` — calling `setState` directly inside `useEffect` **fails lint**; adjust state during render or seed it from props instead.

Build facts (verified locally): `next build` loads `.env` and passes **with the backend on :8000 stopped** — no services needed. During "Generating static pages" it prints `Failed to load new arrivals: ... DYNAMIC_SERVER_USAGE` from `src/components/new-arrivals.tsx` — expected noise; `/` just stays dynamic (ƒ). No `[Better Auth]: Social provider github ...` warning appears — `src/lib/auth.ts` only adds the github provider when both creds are set (they are absent here).

## Environment

- `.env.example` is the tracked template; this tree already has a populated `.env` (Next loads it in dev and build; `.env.local` takes precedence — **restart the dev server after editing `.env`**). The full deploy/env matrix lives in `README.md`.
- Backend is a **separate repo, `../booknook-server`** (`index.js`, Express + MongoDB, db `booknook`; `npm start` = plain `node index.js` — **no watcher, so restart it manually after editing**). Pages still render without it, but degraded: homepage NewArrivals notice, `/all-books` error toast, detail/borrow/books failure states, `/profile` zero counts.

### Backend API auth — read before touching any `fetch`

- Every backend route **requires `authorization: Bearer <Better Auth JWT>`** except `GET /`, `GET /books`, `GET /books/new-arrivals`. Missing/invalid token → **401**; path email ≠ token email → **403**.
- Get the token with `getTokenFromServer()` (`@/lib/getTokenFromServer`, server components) or `getTokenFromClient()` (`@/lib/getTokenFromClient`, client components) and send `headers: { authorization: \`Bearer ${token}\` }`. These wrap the Better Auth `jwt()` / `jwtClient()` plugins registered in `src/lib/auth.ts` / `src/lib/auth-client.ts`.
- The backend verifies JWTs against `${FRONTEND_BASE_URL}/api/auth/jwks`, so the backend needs `FRONTEND_BASE_URL` set to the frontend origin (README documents this).
- **Never send the token to third-party uploads** — the ImgBB upload requests (add-book + my-books edit dialog) must stay header-less; they authenticate only via the `?key=` query param.

### Env vars (only `NEXT_PUBLIC_*` exist in the browser)

- `BACKEND_BASE_URL` — server-side fetches (`my-borrows`, `my-books`, `profile` fall back to `NEXT_PUBLIC_…` then `localhost:8000`; `all-books/[id]/page.jsx` uses it bare).
- `NEXT_PUBLIC_BACKEND_BASE_URL` — browser-side (catalog, add-book, borrow modal, return, my-books actions). Falls back to `http://localhost:8000` **only when `NODE_ENV === "development"`**; a production build without it throws "not configured". Trailing slashes are stripped before use.
- `BACKEND_NEW_ARRIVEL_URL` — homepage only; the `ARRIVEL` misspelling is intentional — match it exactly. Current value path is `/books/new-arrivals`. If unset, `new-arrivals.tsx` **throws** (config error — no fallback).
- `MONGO_DB_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` — read at module scope by `src/lib/auth.ts`, which throws immediately when `MONGO_DB_URL` is missing.
- `NEXT_PUBLIC_IMGBB_API_KEY` — ImgBB cover upload on `/add-book` and in the `/my-books` edit dialog (exposed to browsers by design; missing key = toast error, not a crash).
- `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` — optional; both or no GitHub provider at all. The Google buttons in `/login` and `/register` are stubs that only show an info toast.

## Project structure

- **App Router** (`src/app/`) — `/`, `/all-books`, `/all-books/:id`, `/add-book`, `/login`, `/register`, `/my-books`, `/my-borrows`, `/profile`, `/api/auth/[...all]`. Root layout = `ThemeProvider` + `Navbar` + `main` + `Toaster` (sonner) + `Footer`; theme awareness comes from it, so **don't wrap new pages in `ThemeProvider` again**.
- **Route protection — `src/proxy.ts`** (Next 16's middleware replacement; the build prints `ƒ Proxy (Middleware)`). It redirects unauthenticated requests for `/add-book`, `/my-books`, `/my-borrows`, `/profile`, `/all-books/:path` (detail pages; the `/all-books` list itself is public) to `/login?callbackUrl=<path+query>` — `/login` reads that param (same-site paths only) and returns the user there after sign-in, else `/`. **A new private route must be added to its `config.matcher`** — pages keep their own sign-in prompts only as a second line of defense.
- **Page titles** — every route exports `BookNook | <Page>` instead of the generic root `BookNook`: server pages (`/`, detail, `/my-books`, `/my-borrows`, `/profile`) export `metadata` directly; client pages (`/all-books`, `/add-book`, `/login`, `/register`) can't export metadata, so each has a pass-through `layout.tsx` that does (page-level metadata beats layout, so the detail page's own title wins over `all-books/layout.tsx`).
- **Fetch split** — server components fetch in `new-arrivals.tsx` (homepage), `all-books/[id]/page.jsx`, `my-borrows/page.tsx`, `my-books/page.tsx`, `profile/page.tsx`; client pages/components fetch in `all-books/page.tsx`, `add-book/page.tsx`, `BorrowBookModal.jsx`, `my-borrows-list.tsx`, `my-books-list.tsx`. Backend endpoints (strict `/books` + `/borrows` naming): GET `/books`, GET `/books/new-arrivals`, GET `/books/:id`, GET `/books/user/:email`, POST `/books`, **PATCH** `/books/:id` (update is PATCH, not PUT), DELETE `/books/:id`, POST `/borrows`, GET `/borrows/:email`, DELETE `/borrows/:id` — all but the first two need the Bearer token. Books carry an `availableCopies` counter (seeded from `totalCopies` on `POST /books`) that the borrow/return routes `$inc` ±1.
- **Components** (`src/components/`) — shadcn/ui primitives in `ui/` (config `components.json`, style `base-nova`, lucide icons — add more with `npx shadcn add <name>`) + custom ones (navbar, footer, banner, new-arrivals, top-categories, borrowing-steps, reader-reviews, home-navigation).
- **Lib/hooks/contexts** — `@/lib/auth.ts` (server Better Auth, MongoDB adapter, `jwt()` plugin, `autoSignIn: false`), `@/lib/auth-client.ts` (browser client, `jwtClient()` plugin, no `baseURL` → same-origin `/api/auth/*`; exports `useSession`), `@/lib/utils.ts` re-exports `cn` from the `cn` package, `@/hooks/use-mobile.ts` (`useIsMobile`, 768px), `@/contexts/ThemeContext.tsx` (toggles `.dark` on `<html>` — **no persistence, resets on refresh**).
- **Fonts/aliases** — `next/font` supplies `--font-playfair`, `--font-inter`, `--font-geist-mono` (never `import` them manually). `@/` → `./src/*`; use it everywhere.

## Key quirks

- **Borrow flow is enforced in the backend, not the UI.** POST `/borrows`: **409** if you already have an active loan of that book, **400** when out of stock, **403** if body `borrowerEmail` ≠ token email. The backend overwrites `borrowerName`/`borrowerEmail` from the JWT, inserts the record, then decrements atomically — `updateOne({ _id, availableCopies: { $gt: 0 } }, { $inc: { availableCopies: -1 } })` — so concurrent borrows can never oversell the last copy; if the guarded update matches nothing, the loan record is rolled back and the request gets **400**. `all-books/[id]/BorrowBookModal.jsx` surfaces the server's `message` in its error toast and calls `router.refresh()` on success; the detail page passes the session `user`, making the name/email inputs read-only. `page.jsx` reads `availableCopies ?? totalCopies`; at 0 the cover badge and button both say "Not Available".
- **Navbar owns the session.** `navbar.tsx` calls `authClient.useSession()` directly and gates nav links on login — don't look for a `user` prop. Its dropdown "My Profile" links to `/profile` (session-gated server page rendering `profile-client-view.tsx`: name/email/avatar, live Books Added + Active Borrows counts, edit form saving via `authClient.updateUser` → `POST /api/auth/update-user`, then `router.refresh()`). Counts come from `GET /books/user/:email` and `GET /borrows/:email` (both Bearer-authed; the latter is `find({ borrowerEmail })`, 403 on email mismatch). `profile/page.tsx` filters out `status === "returned"` itself.
- **`/my-books`**: server `page.tsx` — `auth.api.getSession({ headers: await headers() })`, sign-in prompt when logged out, `GET /books/user/:email` (`cache: "no-store"`, degrades to a failure state), then `my-books-list.tsx` (client): books whose `addedBy.email` matches the session, with a shadcn **Dialog** edit form (**PATCH** `/books/:id` with Bearer token; backend answers `{ success, message, result }` and the list updates from `result`) and an **AlertDialog** delete confirm (DELETE `/books/:id` with Bearer; the file's "409 while on loan" comment is stale — the backend has no such check). Base UI gotchas: `AlertDialogContent` renders **no close X** — the page adds its own (an `AlertDialogCancel` styled as X), and `AlertDialogAction` is a plain `Button` that does **not** auto-close — `handleDelete` closes the dialog itself on success. Local list state is seeded from props with **no effect** (`react-hooks/set-state-in-effect` fails lint).
- **`/my-borrows`**: server `page.tsx` fetches `GET /borrows/:email` for the session (Bearer, `no-store`, degrades to a failure state) and renders `my-borrows-list.tsx` (client), whose "Return Book" button `DELETE`s `/borrows/:id` (record is **deleted**, not marked returned — so returned books vanish from both tables; the archive only shows records already `status: "returned"`, which this UI never creates), drops the row from local `removedIds` state, then `router.refresh()`s.
- **`/add-book` attributes `addedBy` to the real session** (`useSession`) — though the backend overwrites `addedBy` from the verified JWT anyway — and `/my-books` filters on `addedBy.email`. This pairing is load-bearing; don't reintroduce hardcoded attribution.
- **Auth flow** — `/register` calls `authClient.signUp.email` then `router.push("/login")`; `/login` pushes the validated `?callbackUrl=` (from the proxy redirect) or `/` on success; logout is `authClient.signOut` in the navbar. `autoSignIn: false`, so sign-up does **not** issue a session cookie — sign in separately.
- **Mixed JS/TS** — only `all-books/[id]/page.jsx` and `BorrowBookModal.jsx` are `.jsx`, and only `page.jsx` is listed in tsconfig `include`. Write new code as `.tsx`.
- **React Compiler** (`experimental.reactCompiler: true` in `next.config.ts`) is on — don't assume classic RSC/`useState` ordering conventions. Also `cacheComponents: false`.
- **Tailwind v4 via Turbopack** — `*.css` runs through `@tailwindcss/turbopack`; editing `globals.css` needs a full reload. The important modifier is the v4 suffix form (`class!`), and `cn()` merges via tailwind-merge (same-variant conflicts: last wins; different-variant conflicts: **both** kept, so CSS order decides).
- **External images** — `next.config.ts` `images.remotePatterns` allows `images.unsplash.com`, `i.ibb.co`, `**.ibb.co`, `imgbb.com`, `**.postimages.org`, `localhost`. Add new hosts there. The `/my-books` edit dialog previews covers with a raw `<img>` (eslint-disabled) because user-typed URLs may fall outside `remotePatterns`.
- **New page** → `src/app/<route>/page.tsx`, pull UI from `@/components/ui/...`; if it's private, add it to the `src/proxy.ts` matcher, and give it a `BookNook | ...` title (page `metadata` export, or a `layout.tsx` when the page is a client component).
